# naverblogbot 설계 (2026-10-01)

## 목표

맛집 방문 사진과 한 줄 소감을 넣으면, 상위 노출 맛집 글의 형식(가운데 정렬, 짧은 줄, 인용구 소제목, 지도, 태그)을 따른 리뷰 초안을 만들고, 봇 전용 크롬 창의 네이버 에디터에 제목·사진·본문을 입력한 뒤 **발행 직전에 멈춘다.** 발행은 사람이 검토 후 직접 한다.

배포 형태는 Windows exe 한 개. 더블클릭하면 창이 뜬다.

근거 문서:
- 사용자 로드맵 문서 "네이버 블로그 체험단 12주 로드맵"의 '자동 글쓰기 봇 규칙'
- `docs/research/2026-10-01-top-posts-analysis.md` (상위 글 90개 실측)

## 범위 밖

- 발행 버튼 클릭, 예약 발행, 여러 글 일괄 처리
- 체험단 사이트 신청·배너 코드 삽입 (배너는 사용자가 직접 붙여넣고, 체크리스트로 안내)
- HEIC 변환 (HEIC 사진이 있으면 JPG로 바꾸라고 안내)
- 맥·리눅스 지원

## 사용 흐름

1. exe 실행 → 첫 실행이면 설정 창: Anthropic API 키, (선택) 내 글 예시 2~3개 붙여넣기
2. 메인 창에서 사진 폴더 선택, 입력란 채우기
3. [초안 만들기] → 약 1분 → 제목 후보 3개, 본문 미리보기, 체크리스트 표시. 같은 폴더에 `draft.json`, `draft.html` 저장
4. 제목 후보 하나 선택 → [네이버 에디터에 입력]
5. 봇 전용 크롬 창이 열림 (처음엔 네이버 로그인 필요, 이후 유지) → 글쓰기 화면에서 순서대로 입력 → "검토 후 직접 발행하세요" 안내
6. 사용자가 체크리스트대로 확인(광고 배너, 확인 표시 항목, 모자이크) 후 발행

## 입력 (메인 창)

| 항목 | 필수 | 비고 |
|---|---|---|
| 사진 폴더 | 필수 | jpg/jpeg/png/webp. 13장 미만이면 경고, 계속 가능 |
| 가게명, 동네 | 필수 | 제목·태그 키워드 |
| 한 줄 소감 | 필수 | 묘사의 유일한 재료 |
| 내돈내산 / 협찬 | 필수 | 협찬이면 업체명(또는 체험단명) 필수 |
| 먹은 메뉴·가격 | 권장 | 비우면 메뉴판 사진에서 읽고 「확인: …」 표시 |
| 아쉬운 점, 추천 대상 | 권장 | 비우면 "이 내용 없이 쓸까요?" 확인 창. 봇이 지어내지 않음 |
| 웨이팅·주차·영업시간 | 선택 | 비우면 언급하지 않음 |
| 캠페인 가이드 | 협찬 시 권장 | 필수 키워드·사진 수·글자 수를 붙여넣기 |

## 구성 요소

패키지 `naverblogbot/` (단일 책임 모듈):

| 모듈 | 역할 |
|---|---|
| `settings.py` | `%APPDATA%\naverblogbot\settings.json` 읽기·쓰기 (api_key, model, style_samples) |
| `inputs.py` | `ReviewInput` 데이터클래스, 필수값 검증 |
| `photos.py` | 폴더 사진 목록(EXIF 촬영시각 정렬), API 전송용 축소본 생성(긴 변 1568px, EXIF 회전 반영), 원본은 업로드용으로 그대로 |
| `rules.py` | 분석에서 나온 기준값 상수 (줄 길이, 글자 수 범위 등) |
| `writer.py` | 프롬프트 구성 + Claude 호출 1회 → `Draft` |
| `draft.py` | `Draft` 구조, 코드 후처리(줄 재분할, 광고 문구 삽입, 해시태그 줄), 검사 → 경고 목록 |
| `preview.py` | `draft.html`(미리보기 + 체크리스트), `draft.json` 저장 |
| `history.py` | 최근 초안 3개의 첫·끝 문장 보관 → 다음 프롬프트에 "반복 금지"로 전달 |
| `editor.py` | Playwright로 전용 크롬 열기, 로그인 대기, 글쓰기 화면 입력 |
| `app.py` | tkinter 창. 작업은 백그라운드 스레드에서 실행해 창이 멈추지 않게 함 |
| `run.py` (루트) | PyInstaller 진입점 |

## Draft 구조 (Claude 구조화 출력)

```json
{
  "titles": ["...", "...", "..."],
  "blocks": [
    {"type": "quote", "text": "📍 위치·영업정보"},
    {"type": "lines", "lines": ["판교역에서 걸어서", "5분 거리라", "점심에 가기 좋았어요"]},
    {"type": "photo", "file": "IMG_0412.jpg"},
    {"type": "map"},
    {"type": "blank"}
  ],
  "tags": ["판교맛집", "..."],
  "photos": [{"file": "IMG_0412.jpg", "kind": "exterior|interior|menu|food|other", "has_face": false}],
  "confirm": ["돈가스 12,000원 (메뉴판에서 읽음)"]
}
```

- `blank`은 빈 줄 1개. `lines` 블록 안에서는 빈 줄을 쓰지 않는다.
- 본문의 「확인: …」 표시는 `confirm` 항목과 1:1.
- 광고 문구, 해시태그 줄은 Claude가 아니라 코드가 넣는다.

## 글쓰기 규칙 (프롬프트 + 코드 검사)

프롬프트에 넣는 규칙 (분석 기준값):
- 사실은 입력에서만. 맛·양·친절·가격·영업시간을 추측하지 않는다. 사진에서 보이는 것과 소감만 묘사 재료
- 구성: 도입(2~4줄) → 📍 위치·정보 인용구 + 정보 줄 + 지도 → 외관·내부 → 메뉴판·가격 → 음식 사진마다 2~6줄 → 총평 인용구(✔ 추천 대상, 아쉬운 점, 재방문 의사)
- 한 줄은 구절 단위, 22자 이하(목표 14~20자), 2~3줄마다 빈 줄
- 본문 1,500~2,300자(공백 제외). 캠페인 가이드 수치가 있으면 그게 우선. 글자 수를 채우려고 같은 말 반복 금지
- 문장 끝은 ~요 위주에 ~다를 섞음, ㅎㅎ는 글당 2회 이하. 내 글 예시가 있으면 그 어미·문장 길이를 따름
- 이모지 5~10개, 인용구 소제목과 ✔ 목록 앞에만
- 제목 3개: 30~45자, `동네+맛집 키워드 → 가게명 → 메뉴 → 수식어`. 협찬이면 가이드 필수 키워드 포함
- 태그 10~20개, 절반은 동네명 조합(동네맛집, 동네역맛집, 동네+메뉴), 가게명·가게명+지점, 상황(데이트·점심·회식)
- 사진은 모두 정확히 한 번씩 배치. 사람 얼굴이 식별되면 `has_face: true`
- 최근 초안의 첫·끝 문장과 같은 문장 금지

코드 후처리:
- 22자 넘는 줄은 띄어쓰기 기준으로 재분할
- 협찬이면 맨 앞에 `[협찬] 이 글은 {업체명}으로부터 식사를 무상으로 제공받아 작성했습니다.` (굵게). 옵션으로 끄거나 옮길 수 없음
- 본문 끝에 해시태그 줄 추가 (상위 글 48%가 본문 끝 해시태그 사용)

코드 검사 → 체크리스트 경고 (재요청은 하지 않음. 부족한 건 지어내지 않고 사용자에게 알림):
- 글자 수 1,100 미만 또는 2,745 초과, 사진 13장 미만
- 빠진 사진, 없는 파일명 참조
- 이모지 12개 초과
- 협찬인데 가이드 필수 키워드 누락

체크리스트 고정 항목: 체험단 배너 맨 위 삽입(협찬), 광고 문구 크기·색 확인, 「확인」 표시 해결, 얼굴 모자이크 대상 사진, 지도 위치 맞는지.

## Claude 호출

- 모델 기본값 `claude-opus-5`, 설정에서 변경 가능. 서버 측 거절 폴백(`fallbacks: "default"`) 사용
- 사진은 축소본을 base64 이미지 블록으로, 각 사진 앞에 파일명 텍스트 블록
- 구조화 출력(JSON 스키마)으로 받는다. 응답이 스키마와 다르면 오류 표시
- 회사망 대응: 앱 시작 시 `truststore.inject_into_ssl()`
- 예상 비용: 사진 15장 기준 입력 약 3만 토큰 + 출력 약 6천 토큰 → 글당 약 0.3달러

## 에디터 입력 (editor.py)

- `launch_persistent_context(user_data_dir=%LOCALAPPDATA%\naverblogbot\chrome-profile, channel="chrome", headless=False)`. 크롬이 없으면 `channel="msedge"`
- 글쓰기 페이지 열기 → 로그인 화면이면 "창에서 로그인하세요" 안내 후 글쓰기 화면이 될 때까지 대기(최대 5분)
- 입력 순서: 제목 → 가운데 정렬 → (협찬) 굵게 광고 문구 → 블록 순서대로: `lines`=줄마다 입력+Enter, `blank`=Enter, `quote`=인용구 버튼 후 입력, `photo`=사진 버튼 → 파일 선택창에 원본 경로, `map`=장소 버튼 → 가게명+동네 검색 → 첫 결과 추가 → 해시태그 줄
- 지도 검색 결과가 없거나 실패하면 해당 위치에 `[지도: 가게명]` 텍스트를 넣고 체크리스트에 표시
- 에디터 화면 요소 선택자는 `editor.py` 상단 상수로 모은다. 네이버가 화면을 바꾸면 여기만 고친다
- 입력 중 오류가 나면 거기서 멈추고 몇 번째 블록에서 실패했는지 표시. 초안 파일은 이미 저장돼 있어 수동 복붙 가능
- 발행 버튼과 발행 설정 창은 건드리지 않는다

## 배포

- PyInstaller 단일 exe(`naverblogbot.exe`), Playwright 드라이버 포함, 브라우저는 설치된 크롬/엣지 사용
- GitHub Actions(`windows-latest`): `v*` 태그 푸시 시 테스트 → 빌드 → Release에 exe 첨부
- 코드 서명 없음 → 첫 실행 시 SmartScreen "추가 정보 → 실행" 안내를 README에 기재

## 테스트

- 단위 테스트(pytest): inputs 검증, photos 정렬·축소, draft 후처리·검사, writer 요청 구성(Claude 클라이언트는 가짜 객체), preview 렌더링, settings 저장, history
- 실제 Claude 호출 1회: 샘플 사진 폴더로 초안 생성해 형식 확인 (API 비용 발생, 사용자 키 필요)
- 에디터 입력: 자동 테스트 없음. 실제 네이버 계정으로 수동 확인 (선택자 확인을 위해 구현 중 사용자가 전용 창에서 1회 로그인 필요)
- exe: 빌드 후 이 PC에서 실행해 창이 뜨고 초안 생성까지 되는지 확인

## 위험

| 위험 | 대응 |
|---|---|
| 네이버 에디터 화면 변경으로 입력 실패 | 선택자 한 곳에 모음, 실패 시 초안 파일로 수동 진행 |
| 네이버의 자동화 감지·정책 | 한 번에 한 글, 사용자가 실행, 발행은 사람. 대량·예약 기능 없음 |
| 지어낸 후기 | 사실은 입력에서만, 빈 판단 항목은 확인 창, 「확인」 표시 |
| 광고 표기 누락 | 코드가 강제 삽입, 체크리스트에 배너 안내 |
| exe 크기·실행 속도 | 단일 exe는 시작 시 압축 해제로 5~10초 걸릴 수 있음. 문제 되면 폴더형 배포로 전환 |
